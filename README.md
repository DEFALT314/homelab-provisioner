# homelab-provisioner

Terraform + Ansible pipeline for a Proxmox homelab. Creates LXC containers,
installs Docker, deploys `docker-compose` services, and registers them in
Nginx Proxy Manager.

## Motivation

Self-hosting a service used to be a sequence of manual steps: create a
container in the Proxmox UI, install Docker, copy a compose file, run it,
add a reverse proxy entry. Repeat for every service, and keep it consistent
every time something changes.

This project splits the work between two tools that each do one thing:

- **Terraform** provisions the infrastructure (LXC containers) and writes the
  data Ansible needs.
- **Ansible** configures each container (Docker, compose, reverse proxy).

Adding a new service means writing two small files and running one script.

## How it works

```
service.yml  →  terraform apply  →  LXC containers
                                       │  writes inventory.yml + services.yml
                                       ▼
                                  ansible-playbook
                                       │
                                       ▼
                              Docker + compose  ←── NPM ──→  domain
```

1. `terraform apply` creates one unprivileged LXC container per service
   (Debian template, static IP) and generates the Ansible inventory and
   service list.
2. The `docker` role installs Docker Engine and the Compose plugin from
   Docker's official apt repository.
3. The `docker_service` role syncs the service directory to
   `/opt/service/<name>/` and runs `docker compose up -d`.
4. The `nginx_proxy_manager` role calls the NPM REST API and creates one
   proxy host per service (domain → container IP:port).

## Requirements

- Proxmox with a Debian LXC template (`local:vztmpl/debian-13-standard_...`)
- Terraform
- Ansible core with the `community.docker` and `ansible.posix` collections
- SSH access to the containers (`~/.ssh/id_ed25519`)
- A running Nginx Proxy Manager instance

## Configuration

```
cp .env.example .env
```

`.env` is the single place for secrets and environment-specific values:

| Variable | Description |
|---|---|
| `TF_VAR_proxmox_token` | Proxmox API token |
| `TF_VAR_default_password` | default root password for new containers |
| `NPM_URL` | NPM API URL, e.g. `http://192.168.1.250:81` |
| `NPM_ADMIN_EMAIL` | NPM admin email |
| `NPM_ADMIN_PASSWORD` | NPM admin password |

`.env` is gitignored. Do not commit it.

## Usage

```bash
./deploy.sh
```

`deploy.sh` sources `.env`, runs `terraform apply`, then
`ansible-playbook playbooks/site.yml`. The playbook waits for new containers
to become reachable over SSH before configuring them.

To run the steps manually:

```bash
cd terraform
terraform init
terraform apply

cd ../ansible
ansible-playbook playbooks/site.yml
```

## Adding a service

`services/memos/` is a working example — replace it with your own services.

For each service, create `services/<name>/` with:

- `service.yml.example` — the committed contract template (shown below),
- `docker-compose.yml` — the service itself.

`service.yml.example`:

```yaml
ip_address: "192.168.1.100/24"   # container IP in CIDR
domain: "memos.example.com"       # NPM domain; empty = skip NPM
port: 5230                        # port the app listens on

ssl: false                        # true = request a Let's Encrypt cert
letsencrypt_email: ""             # required when ssl is true
certificate_id: 0                 # existing NPM cert ID, overrides ssl
```

Copy it to a local `service.yml` (gitignored) with your real values:

```bash
cp services/<name>/service.yml.example services/<name>/service.yml
```

`docker-compose.yml` — the service itself. Any additional files in the
directory (config, `.env`) are synced to the container together with the
compose file.

Then run `./deploy.sh`.

## Notes

- Containers use static IPs on purpose: servers get fixed addresses, DHCP is
  for end-user devices. Everything downstream (NPM, DNS) depends on them.
- `host_key_checking` is disabled in `ansible.cfg`; re-enable it outside a
  trusted lab.
